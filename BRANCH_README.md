# Work Summary: Accelerated Platforms Branch

This document summarizes the recent development and configuration updates made in this branch for the **Accelerated Platforms** reference architecture on Google Cloud. Our work in this branch is strictly focused on enhancing inference capabilities by introducing advanced **Speculative Decoding** techniques for vLLM, and streamlining the infrastructure configuration to test and serve these models.

## 1. Advanced Inference & Speculative Decoding

We have heavily upgraded the inference capabilities of our GKE deployments, focusing on performance optimizations using vLLM's Speculative Decoding. This branch introduces Kubernetes manifests and configuration templates for various speculative decoding methods:

* **EAGLE:**
  * Tested with `Llama-3.3-70b-instruct-fp8`
  * Deployed on H100 and RTX Pro 6000 GPUs
* **N-GRAM:**
  * Tested with `Gemma-4-31b-it`
  * Deployed on RTX Pro 6000 GPUs
* **MTP (Multi-Token Prediction):**
  * Tested with `Qwen3.6-35b-a3b`
  * Deployed on RTX Pro 6000 GPUs

These configurations are available as standalone deployment profiles under the `online-inference-gpu/vllm-spec-decoding` directory.

## 2. Tooling & Model Download Refinements

* **HuggingFace Model Downloader:** Refined the model-download kustomization manifests (`model-download/huggingface`) to handle out-of-memory (OOM) issues and improve custom compute class scheduling, ensuring large models required for speculative decoding are efficiently staged.

## 3. How to Run the Deployment

To deploy any of the new speculative decoding profiles to your GKE cluster, use `kubectl apply -k` against the specific kustomization directory for the model and hardware you wish to target. 

For example, to deploy the MTP Speculative Decoding profile for Qwen 3.6 35B on RTX Pro 6000 GPUs:

```bash
kubectl apply -k platforms/gke/base/use-cases/inference-ref-arch/kubernetes-manifests/online-inference-gpu/vllm-spec-decoding/rtx-pro-6000-qwen3-6-35b-a3b-sd-mtp
```

Similarly, you can deploy the other profiles like:
* `h100-llama-3-3-70b-instruct-fp8-sd-eagle`
* `rtx-pro-6000-gemma-4-31b-it-sd-ngram`
* `rtx-pro-6000-llama-3-3-70b-instruct-fp8-sd-eagle`

*Note: Ensure your `kubectl` context is correctly pointed to your target cluster and that the necessary node pools/custom compute classes for the requested GPUs are available.*

## 4. How to Test Performance

Robust benchmarking suites have been created for standard vLLM and each speculative decoding variant. These suites deploy Kubernetes Jobs to run load tests against the deployed inference servers.

To run a benchmark, navigate to the `inference-perf-bench` directory. You will find subdirectories for `sd-eagle`, `sd-mtp`, `sd-ngram`, and standard `vllm`.

**Steps to benchmark (e.g., MTP):**

1. **Configure the benchmark:** Review and run the configuration script to template out the environment variables and configmaps.
   ```bash
   cd platforms/gke/base/use-cases/inference-ref-arch/kubernetes-manifests/inference-perf-bench/vllm-spec-decoding/sd-mtp
   ./configure_benchmark.sh
   ```
2. **Launch the benchmark job:** Use Kustomize to apply the benchmark manifests.
   ```bash
   kubectl apply -k .
   ```
3. **View the results:** Monitor the benchmark Job logs to see the generated metrics (e.g., requests per second, time to first token, input/output tokens per second).
   ```bash
   kubectl logs -f job/vllm-benchmark-job -n <your-namespace>
   ```

*(Metrics generated by these runs, such as the `qwen_metrics.json` outputs, are automatically logged and can be exported for further analysis.)*
